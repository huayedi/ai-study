# 第 8 课讲义：Prompt 收口与 RAG 入门

> 学习方式：以阅读理解为主。文末仅有少量「自检思考」，不是作业清单。  
> 对应阶段：总计划第 3 周收口 → 第 6 周 RAG 前置认知

---

## 一、到今天你已经具备什么

前 7 天实际搭起的是一条 **Chat 应用闭环**：

```text
用户问题
  → 组装 messages（system + 历史 + user）
  → 调用大模型（OpenAI 兼容协议，如 DeepSeek）
  → 校验 JSON（answer / need_human …）
  → 写入会话 / 记录 token 与成本
```

你已经掌握的关键判断：

| 能力 | 含义 |
|---|---|
| 协议与配置 | `provider` 是协议，`base-url`/`model`/`api-key` 才区分厂商 |
| 上下文 | 多轮靠每次重发历史；越长越贵；`max-messages` 从队头裁剪 |
| Prompt | 角色 + 本系统术语 + 输出约束 + 拒答规则 |
| Few-shot | 用示范拉齐「风格与边界」，比空口规则更有效 |
| 边界 | 不编造实时库存/金额；高风险操作要人工 |

这些解决的是：**怎么稳妥地说话、怎么像你们 ERP 助手。**  
还没解决的是：**怎么准确引用你们公司自己的手册原文。**

## 二、为什么还要 RAG（核心认知）

### 2.1 模型「会说」≠「知道你们手册」

大模型训练数据里有通用 ERP 常识，所以能回答：

- 采购订单和入库大概有什么区别  
- 期间关闭后为什么不能过账  

但它**没有**可靠地记住：

- 你们菜单叫「物资请购」而不是「请购单」  
- 你们某份《采购作业指导书》第 3.2 节怎么写  
- 你们四公司隔离的具体制度条文  

Few-shot 和术语表，是在「校正口吻与边界」；  
**不能**当知识库用——示范一多就贵，且永远覆盖不完手册。

### 2.2 RAG 一句话定义

**RAG = Retrieval-Augmented Generation（检索增强生成）**

先把私有文档变成可检索的知识片段；  
用户提问时，先检索出相关片段，再让模型**基于这些片段**生成答案（最好带引用）。

```text
手册/制度文档
    ↓ 解析、切分（Chunking）
文本块
    ↓ Embedding（向量化）
向量库（如 PGVector）
    ↓ 用户提问时检索 TopK
相关片段 + 原问题
    ↓ 再调用大模型
带依据的回答（可附文档名/段落）
```

### 2.3 和 Few-shot 的分工（务必记住）

| | Few-shot / System Prompt | RAG |
|---|---|---|
| 解决什么 | 怎么答（风格、拒答、术语、JSON） | 答什么依据（私有知识） |
| 知识来源 | 你写进提示词的少量示范 | 外部文档库，可更新 |
| 适合 | 规则、态度、输出格式 | 手册、制度、SOP、FAQ |
| 不适合 | 塞整本手册 | 替代权限校验 / 直接改库存 |

一句话：**Prompt 管行为，RAG 管知识。**

### 2.4 为什么 ERP 手册特别适合 RAG

1. 文档多、更新勤（制度一改，重索引即可，不必微调模型）  
2. 强需求「有依据」——业务更信带引用的答案  
3. 权限敏感——后续还可按公司/角色过滤可检索范围  
4. 幻觉有成本——入库、期间、审批答错会影响实操

## 三、RAG 链路拆解（教材级，先懂名字）

后续写代码会按这些模块推进，今天只要求能讲清。

### 3.1 文档解析（Parse）

把 PDF / Word / HTML / Markdown 变成纯文本。  
坑：扫描版 PDF、复杂表格、页眉页脚噪音。

学习阶段优先：**Markdown / 纯文本手册**（你们 `samples/rag-docs/` 就是这个方向）。

### 3.2 切分（Chunking）

把长文切成小块（chunk），例如每块 300～800 字，可重叠一段以免句子被切断。

| 切太大 | 切太小 |
|---|---|
| 检索不准、噪音多、费 token | 缺上下文、答案碎片化 |

ERP 实务经验：按「二级标题 / 业务小节」切，往往比固定字数更稳（后续实现时再练）。

### 3.3 向量化（Embedding）

用 Embedding 模型把每个 chunk 变成一串浮点数（向量）。  
语义相近的句子，向量距离更近——这是「按意思搜」而不是只按关键词。

### 3.4 检索（Retrieval）

用户问题也做成向量，在库里找最相近的 K 条（TopK）。  
进阶还会用：关键词检索（BM25）+ 向量检索混合、重排（Rerank）。  
第一版只需理解 TopK。

### 3.5 生成（Generation）

把检索到的片段塞进提示词，要求模型：

- 只根据片段回答  
- 不知道就说文档不足  
- 最好标明来自哪份文档

这与当前 Chat 的差别是：messages 里多了 **「检索到的资料」** 这一段。

## 五、如何准备学习用文档（方法说明）

目标目录：`erp-ai-assistant/samples/rag-docs/`

### 推荐来源（按优先级）

1. 采购/库存操作手册（脱敏）  
2. 常见报错与处理（运维/实施 FAQ）  
3. 期间、审批、公司隔离相关制度摘录  

### 脱敏原则

去掉或替换：真实客户名、供应商名、账号、内网地址、未公开单号、个人信息。

### 格式建议

- 优先 `.md` / `.txt`  
- 文件头写清：来源、模块、是否脱敏  
- 标题层级清楚（`##` `###`），方便按节切分  

仓库中的 `01-purchase-flow-sample.md` 是**格式示例**，不是你们官方制度；你应用自己的脱敏材料逐步替换/补充到至少 3 份，供后续课使用。
